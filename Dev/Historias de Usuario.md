Las **Historias de Usuario** permiten capturar las necesidades del usuario de forma incremental y facilitan la comunicación y priorización de funcionalidades.

## Formato

> **Como [rol], quiero [funcionalidad], para [beneficio].**

- **Como** → rol del usuario.
- **Quiero** → funcionalidad u objetivo.
- **Para** → beneficio o necesidad que se busca satisfacer.

### Ejemplo

> Como paciente, quiero acceder a la agenda de enfermería, para verificar la disponibilidad horaria del personal.

Las historias de usuario pueden complementarse con [[Criterios de Aceptación]].
