Elemento clave de las metodologías ágiles utilizado para definir funcionalidades desde la perspectiva del usuario.

Permiten que Product Owner, usuarios y desarrolladores puedan discutir y comprender el valor que debe entregar una funcionalidad.

## Estructura
Las historias de usuario siguen la fórmula:

**COMO** `<rol>`  
**QUIERO** `<objetivo>`  
**PARA** `<motivación>`

**Permiten identificar**:
- Quién realiza la acción.
- Qué acción necesita realizar.
- Para qué necesita esa funcionalidad.

## Ejemplo
COMO Cliente  
QUIERO poder buscar transacciones  
PARA detectar gastos innecesarios en mi cuenta.

---

# Descripción de una historia de usuario
Complementa el título aportando contexto.

**Puede incluir:**
- Contexto de uso.
- User flows.
- Casos de uso.
- Links a diseños o mockups.
- Limitaciones.
- Reglas de negocio.

---

# Criterios de aceptación
Son condiciones que permiten validar si una historia de usuario está correctamente implementada.

**Sirven para**:
- Guiar al desarrollador.
- Permitir al equipo QA verificar la funcionalidad.
- Definir cuándo una historia puede considerarse terminada.

## Características

### 1. Atomicidad
Cada criterio debe tener un único resultado:
- Éxito.
- Fracaso.

No debe existir éxito parcial.

### 2. No ambiguos
Deben interpretarse de una única manera.

### 3. Verificables
El cliente debe poder comprobarlos fácilmente.

### 4. Completos
Deben cubrir todos los requisitos funcionales.

---

# Beneficios de las historias de usuario
- Representan requisitos que pueden implementarse rápidamente.
- Requieren poco mantenimiento.
- Mantienen una relación cercana con el cliente.
- Permiten dividir proyectos en pequeñas entregas.
- Facilitan la estimación del esfuerzo.
- Son útiles en proyectos con requisitos cambiantes.
